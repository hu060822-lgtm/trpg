# 交易與契約規格 v0.3（Phase 4，原型）

商店、直接交易、委託、多人契約、隊伍共同資產與交易爭議。程式在 `src/world/economy.ts`，資料庫在 `src/persistence/world-store.ts`，測試在 `tests/economy.test.ts` 與 `tests/world-store.test.ts`。

這一版還沒有任何物價或報酬的平衡數值：商品售價、委託報酬、押金都由玩家自己填。可調的上限和比例在 `config/world.v03.json` 的 `economy`。

## 1. 錢幣與帳本

- 錢幣是角色身上的整數（`coins`），不能是負數。
- **每一筆錢幣移動都寫進帳本**（`world_ledger`），交易類的物品移動也是。帳本只能新增，資料庫拒絕修改或刪除。
- 錢幣只有兩個來源和去處：
  - `GM 發放`（mint）：主 GM 用 `gmGrantCoins` 發錢，必須寫原因；
  - `銷毀`（sink）：殘影到期損失的錢幣，以及全員違約時沒有退回的押金。
  - 其他所有移動都是從一方到另一方。所以任何時候都成立：**所有角色的錢幣＋隊伍金庫＋鎖定中的錢幣＝起始錢幣＋發放－銷毀**。
  - 之後會再加入新的收入管道，例如 NPC 委託與打工（2026-10-28 確認方向，還沒做）。測試每一步都會檢查這條式子，試玩頁的主 GM 帳本下方也會即時對帳。
- 玩家只看得到和自己角色、自己參與的鎖定有關的帳目；主 GM 和仲裁 GM 看得到全部。

## 2. 資產鎖定（escrow）

交易、委託報酬、委託交付、契約押金都先「鎖定」：

- 錢幣從角色身上扣掉，放進鎖定；物品的持有者改成這個鎖定。
- 鎖定中的東西不能再花、再賣、再交易，所以同一筆錢不可能同時押在兩個地方。
- 鎖定只有三種結果：
  - `held`（鎖定中）；
  - `released`（退回原主）；
  - `consumed`（交給對方）。
  - 結算後不能再動。

## 3. 商店

- 玩家可以在自己所在的地點開店（`openShop`），之後可以暫停或恢復營業。
- **上架就是把真的物品放進店裡**：物品的持有者改成這家店，商品清單指向這件物品。不能上架別人的、綁定的、或正在裁決中的物品，也沒有「庫存數字」這種東西。
- 購買條件：
  - 店有營業；
  - 買家人在店的地點；
  - 錢夠；
  - 不是自己的店。
- 購買時錢幣和物品在同一筆操作裡一起移動：要嘛全部完成，要嘛全部不動。
- 購買前會再檢查一次「商品清單指向的物品真的還在這家店裡」。如果物品已經被 GM 摧毀，就回報「庫存與商品不一致」並取消交易，不會扣錢。
- 測試在每一步之後檢查兩個方向：清單上的每件商品都在店裡，店裡的每件物品都在清單上。

## 4. 直接交易

1. 提出方寫好「我出什麼」和「我要什麼」（錢幣＋指定物品）。**提出時就把自己出的東西鎖定。**
2. 對方可以接受或拒絕；提出方在對方回覆前可以取消。
3. 接受時，對方要的東西從接受者身上轉過去，鎖定的東西交給接受者，兩邊在同一筆操作裡完成。接受者的錢或物品不夠時，整筆不動，交易維持待回覆。
4. 拒絕或取消時，鎖定的東西退回提出方。

狀態：待回覆 → 完成／被拒絕／已取消。

接受交易時雙方要在同一個地點，和購買一樣（2026-10-28 確認）。

## 5. 委託

1. 發布者寫標題、條件、報酬和期限。**發布時報酬就鎖定**，委託板對所有人公開。
2. 其他玩家接下委託（同一時間只有一個接案人）。發布者只能在還沒人接的時候取消。
3. 接案人提交：
   - **交付型**（例：交 3 株月光草）：系統檢查物品種類與數量，正確就立刻結算，報酬給接案人、物品給發布者。數量或種類不對直接拒絕。
   - **GM 驗收型**（例：查出走私販下落）：提交後進入「待驗收」，由主 GM 或仲裁 GM 通過或退回。退回時提交的物品還給接案人，可以重新提交。
4. 期限到了還沒完成，報酬自動退回發布者（狀態「逾期」）。

狀態：招募中 → 進行中 → 待驗收 → 完成；另外有已取消、逾期、爭議中。

## 6. 契約（2–6 人）

1. 提出方寫好立約人（自己加上 1–5 人，上限 `contractMaxParties`＝6）、條款、期限，以及每個人的押金。提出時先鎖定自己的押金，並算作已簽署。
2. 其他人簽署時各自鎖定押金。**所有立約人都簽署後契約才生效**；還在等人簽的時候，任何條款都不能履行。
3. 條款有四種：
   - 付錢幣；
   - 交出指定物品；
   - 交 N 件某種物品；
   - 由 GM 確認的條款（例：護送到某地）。
   - 每條條款寫明由誰付出、給誰，兩人都必須是立約人。
   - 前三種由負責的一方自己履行，伺服器只移動條款寫的東西；第四種只有主 GM 或仲裁 GM 能勾選。
4. **只有全部條款都勾選才會變成「已履行」**，這時押金全數退回。只完成一部分的契約永遠不會被標成已履行。
5. 提前結束：
   - 還沒生效的提議，任何一位立約人都可以撤回或拒絕，整份作廢，押金退回；
   - 已生效的契約要所有立約人都提議解約才會解除，押金退回，已履行的條款不會撤銷。
6. 期限到了：
   - 還沒簽署的提議自動作廢；
   - 已生效但沒履行完的契約判定違約。
     - 還有條款沒履行的人都算違約方，其他人是守約方。
     - **有人守約**：每位違約方的押金平分給守約方，除不盡的零頭給排在最前面的守約方（依契約上的立約人順序）。守約方的押金退回。
     - **所有人都違約**：每個人退回押金的 `allBreachRefundRatio`（暫定 50%，無條件捨去），其餘沒收（記為銷毀）。2026-10-28 確認「退回一部分」，比例還沒定。

狀態：待簽署 → 生效中 → 已履行；另外有違約、已取消、爭議中。

## 7. 爭議

- 委託（進行中或待驗收）或契約（生效中）的當事人可以提出爭議。
- 提出後所有鎖定的資產維持凍結，期限結算也會跳過它，直到主 GM 或仲裁 GM 裁決：
  - 委託：付給接案人，或退回發布者；
  - 契約：視為履行、解除契約，或判定一位或多位立約人違約（押金照第 6 節分配）。
- 爭議紀錄保存在 `world_records`，不能刪除。

## 8. 隊伍與共同資產

- 隊長建立隊伍時選擇提領規則：
  - **隊長決定**：隊長可以直接從金庫領錢或物品；
  - **多數決**：每次提領都要投票。
- 一個角色同一時間只能在一支隊伍。隊伍最多 `teamMaxMembers`（暫定 6）人，邀請中的也算。
- 只有隊長能邀請，被邀請的人可以加入或婉拒。
- 隊員可以隨時存入錢幣或物品（自己的、可交易、沒綁定的）。存入的物品持有者改成這支隊伍，帳本記一筆。
- 提領只能給活著的隊員。
- 需要投票的提案：
  - 隊長決定制下非隊長的提領，以及多數決制下所有提領；
  - 改提領規則；
  - 請出隊員（不能請出隊長）；
  - 解散。
- 投票規則：
  - 提案人自動算一票同意。
  - **同意票超過活著隊員的一半就通過並立刻執行**；反對票達到一半就否決。
  - 死亡的隊員不再算進人數。
- 通過時才檢查金庫夠不夠。如果兩個提領案都通過但錢只夠一次，後通過的那個標成「無法執行」，不會付兩次。
- 隊長死亡時，由排在最前面的活著隊員代理隊長。
- 離隊：
  - 存進金庫的東西留在金庫，不會自動分回；
  - 隊長離隊時由下一位隊員接任；
  - 最後一位隊員要先把金庫領完才能離隊。
- 解散要先把金庫清空。
- 隊伍名稱和成員是公開的。金庫、投票、邀請和隊伍持有的物品只有隊員看得到（主 GM、仲裁 GM 看得到全部）。

## 9. 重複請求與同時操作

- **所有交易類操作都要帶 `requestId`**（客戶端產生）。伺服器在同一個交易裡記下這個 id 和結果。
  - 同一個 id 再送一次時，不會重新執行，而是回傳第一次的結果（`replayed: true`）。所以玩家連點兩次「購買」只會扣一次錢。
  - 同一個 id 拿去做別的操作，或換人使用，會被拒絕。
- 兩個人看著同一個畫面同時買同一件商品時，物品那一列的版本號只允許一個人成功；另一個人會收到「請重新讀取」，錢不會被扣。
- 隊伍、商店、交易、委託、契約、鎖定、爭議都是 `world_records` 裡帶版本號的一列，資料庫拒絕刪除。
